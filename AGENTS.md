# Agent Instructions

This project follows a design -> implementation -> phases flow:

1. `design/` — the _what_ and _why_. Write or update a design doc here before
   writing any implementation. No code, no architecture decisions here.
2. `implementation/` — the _how_. Implementation docs must discuss the
   architecture options that were considered and the tradeoffs between them, not
   just record the final choice.
3. `PHASES.md` — the high-level phases of building this project. Keep it
   updated directly as phases are added, started, and completed.

When working in this repo, read `design/` first, then `implementation/`, then
check `PHASES.md` for what's in progress before writing code.
